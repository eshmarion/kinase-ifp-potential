# kinase-ifp-potential

Потенциал на основе отпечатка межмолекулярных взаимодействий (IFP) для отбора
и уточнения лигандов киназ, сгенерированных диффузионной моделью
[DiffSBDD](https://github.com/arneschneuing/DiffSBDD)
([Schneuing et al., Nature Computational Science, 2026](https://www.nature.com/articles/s43588-024-00737-x)).

Отпечаток считается по карману киназы в разметке KLIFS: 85 позиций × 7 типов
взаимодействий. Скор молекулы — доля ключевых взаимодействий эталонного лиганда,
которые она воспроизводит. По этому скору выдача модели переранжируется, а положение
лиганда уточняется градиентным спуском.

## Установка

Основной способ — контейнер: одинаковое окружение везде, ставить нужно только Docker.

```powershell
docker compose run --rm dev pytest          # проверки
docker compose run --rm dev bash            # интерактивная оболочка
```

Запасной путь, если Docker не встаёт, — `uv` (требуется Python 3.10):

```powershell
uv sync --all-extras --group dev
```

## Воспроизведение

```powershell
docker compose run --rm dev python scripts/reproduce.py --list    # состав конвейера
docker compose run --rm dev python scripts/reproduce.py --check   # пересчитать и сверить
```

Этапы помечены по тому, что им нужно:

| Метка | Что считает | Входит в `--check` |
|---|---|---|
| `cpu` | отпечатки, метрики, скор, переранжирование, таблицы | да |
| `figures` | рисунки | да, по числам панелей: PNG зависит от версии matplotlib |
| `network` | выгрузка KLIFS | нет: внешняя база может ответить иначе |
| `heavy` | докинг Vina, физичность PoseBusters | нет: минуты-десятки минут |
| `gpu` | генерация молекул в облаке | нет: нужны GPU и токен |

## Как это устроено

**От структуры к числу.** Из базы KLIFS выгружаются структуры киназ, мишень
отбирается процедурой по разрешению и оценке качества, а не называется вручную.
Пакет мишени (`data/targets/<pdb_id>/`) содержит белок, карман, кристаллический
лиганд и паспорт `target.json` с разметкой позиций. По паспорту и молекуле
считается отпечаток: для каждой из 85 позиций кармана — какие из 7 типов
взаимодействий реализованы. Отпечаток молекулы сравнивается с эталонным
отпечатком кристаллического лиганда; доля воспроизведённых ключевых взаимодействий
и есть скор.

**Почему расчёт отделён от работы с прогонами.** `src/kinase_ifp/` считает химию
и ничего не знает о папках: та же функция скора служит целевой функцией при
уточнении положения, и тянуть за собой работу с файлами ей незачем. Всё, что
касается прогонов — паспорта, реестр, ранжирование, сборка таблиц, — живёт
в `src/experiments/`, а оценка результата в `src/evaluation/`.

**Что где лежит.** `data/` — выгрузка KLIFS, пакеты четырёх мишеней и реестр
измерений. `runs/` — папки прогонов: молекулы, метрики по молекулам, ранжирование
и паспорт. Прогоны хранятся, а не пересобираются: генерация требует GPU
и токена облака, и повторить её может не каждый. `results/` — то, что собирается
из прогонов: таблицы, отчёты, рисунки и числа к ним.

**Воспроизводимость.** Паспорт прогона несёт контрольную сумму пакета мишени
и режим протонирования; расчёт отказывается считать, если пакет на диске
не совпадает с тем, на котором прогон сделан. Отпечатки, посчитанные при разных
режимах протонирования, несопоставимы, и без этой проверки расхождение проявилось бы
не ошибкой, а неверными числами. Туда же пишутся версии библиотек, от которых
зависит результат.

**Границы работы.** Модель DiffSBDD не изменялась: её клон закреплён коммитом
`5d0d38d` и монтируется в образ только на чтение. Потенциал применён **после**
модели — переранжированием выдачи и уточнением положения; во всех паспортах
`guidance_scale: 0.0`. Дифференцируемая версия потенциала написана
(`src/soft_potential/`), но в контур генерации не включена.
